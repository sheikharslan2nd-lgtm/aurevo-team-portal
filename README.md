# Aurevo System — Team Portal (Django)

A Django-based team portal with:
- Member registration and login
- New registrations stay **Pending** until an admin approves them
- Member profile details
- Explore panel: **all countries → all cities → all niches → all sub-niches + micro-niches**
- 3-level niche hierarchy (main niche → sub-niche → micro-niche)
- Country → city targeting, niches, outreach methods, strategy notes
- Daily activity reports
- Admin dashboard for members, reports, strategies and reference data
- Black / white / neon-lime UI
- PostgreSQL-ready deployment, with SQLite for local development

## 1. Run locally (Windows)

Install Python 3.12+ and Git if needed. Open a terminal in this folder:

```powershell
py -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py seed_locations
python manage.py createsuperuser
python manage.py runserver
```

Open `http://127.0.0.1:8000/`.
- Team portal: `/`
- Django admin: `/admin/`

For local use, SQLite is created automatically as `db.sqlite3` after `migrate`.

## 2. Database code

The database schema is defined in `portal/models.py`. Django creates tables using migrations:
```bash
python manage.py makemigrations portal
python manage.py migrate
```
The initial migration is included in `portal/migrations/0001_initial.py`.

`python manage.py seed_locations` fills the reference data from the bundled files in `date/`:

- **Countries and cities** — `date/worldcities.csv` (≈48,000 cities across ≈250 countries), merged with the curated city list. Countries are keyed by ISO-3166 code, so names such as `Pakistan` / `Islamic Republic of Pakistan` are stored as one row instead of duplicates.
- **Niches** — `date/nichess.html` supplies the main niches and their sub-niches. Business categories get curated sub-niches from `portal/niche_data.py`, and every sub-niche gets deterministic micro-niches generated by `generate_micro_niches()`.
- **Outreach methods** — the standard method list.

The command is idempotent and safe to re-run; existing rows are reused rather than duplicated. It also accepts:

```bash
python manage.py seed_locations --skip-locations   # niches + methods only
python manage.py seed_locations --skip-niches      # countries + cities only
```

After seeding, the dashboard shows the full explorer. Everything is still editable in Django Admin under **Countries**, **Cities** and **Niches**; sub-niches are niches whose parent is a main niche, and micro-niches are niches whose parent is a sub-niche.

### Using the explorer

The dashboard has four linked columns:

1. **All countries** — every seeded country, with its city count. Use the search box to filter.
2. **Cities** — clicking a country loads **all** of its cities (no truncation).
3. **All niches** — every main niche, with its sub-niche count.
4. **Sub & micro niches** — clicking a niche shows every sub-niche; each one expands to reveal all of its micro-niches.

Clicking a country, city, niche, sub-niche or micro-niche automatically fills the **Save a strategy** form below. Saving stores the most specific niche chosen (micro-niche if selected, otherwise sub-niche) and the table shows the full path, e.g. `Dental Clinics / Cosmetic Dentistry / Best Cosmetic Dentistry`.

## 3. Free deployment option (Render + external PostgreSQL)

This project is configured for Render. Free plan terms and database-provider limits can change; check the providers' current pricing before production use. Render's free web service may sleep when idle, and free database providers can have limits.

1. Push this folder to a private or public GitHub repository.
2. Create a free PostgreSQL database with a provider such as Neon. Copy its PostgreSQL connection string (`postgresql://...`). Use the provider's pooled connection string if its docs recommend it for serverless/hosted apps.
3. In Render, choose **New → Blueprint** and connect your repository. Render reads `render.yaml`.
4. In the Render service environment, set `DATABASE_URL` to the PostgreSQL connection string. Do not commit this URL to GitHub.
5. Deploy. The build script runs `collectstatic` and `migrate`.
6. Once deployed, open the Render shell (or use Render's one-off shell if available) and run:
   ```bash
   python manage.py createsuperuser
   python manage.py seed_locations
   ```
   If shell access is not available on the free plan, create a superuser using a temporary one-off command supported by your host, or run the project locally with the same `DATABASE_URL`:
   ```bash
   python manage.py createsuperuser
   python manage.py seed_locations
   ```
7. Visit `/admin/`, log in, add cities/niches/methods, and approve team members.

### Important deployment notes
- Never share `DJANGO_SECRET_KEY` or `DATABASE_URL`.
- `DEBUG=False` is configured for deployment.
- The app trusts `ALLOWED_HOSTS` from environment variables. If you use a custom domain, add it to `ALLOWED_HOSTS`, e.g. `.onrender.com,aurevosystem.site`.
- Set `CSRF_TRUSTED_ORIGINS` if using a custom domain, e.g. `https://aurevosystem.site`.
- This is a starter project. Before onboarding a large team, add rate limiting, audit logging, automated backups, email verification/password reset, and review the host's persistent storage/database limits.
- A hidden URL is not access control. This portal uses Django authentication and staff permissions for admin access.
